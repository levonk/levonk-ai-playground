# Out of Scope: 2026-08-01

This file records what the levonk-ai-playground repo explicitly does NOT do.
Check here before proposing a feature — it may have been deliberately excluded.

## Not a multi-host orchestrator

This repo deploys vLLM models on a **single** GPU machine. It does not:

- Manage fleets of GPU hosts
- Schedule models across multiple nodes
- Provide a control plane or API gateway in front of vLLM
- Do load balancing between model instances

For multi-host orchestration, use a separate scheduler (Ray Serve, Kubernetes,
etc.). This repo's scripts are intentionally single-machine, as documented in
the README's "Why Shell Library Instead of Ansible?" section.

## Not an Ansible playbook collection

The README explicitly chose a shell library over Ansible for this use case
(local development playground, single-machine Docker deployment). Do not
convert the scripts to Ansible roles/playbooks. Ansible adds inventory and
Python dependencies that are not justified for a single-host playground.

## No automated test suite or CI

There is no `tests/` directory, no CI workflow, and no `justfile`. The
`devbox.json` references `just` targets inherited from rtk bundles, but this
repo has no project-specific build/test/lint pipeline. Verification is manual
(run the model script, then `test-query.sh`). Adding a CI pipeline is an
improvement candidate, not a current scope item — see
`internal-docs/improvements/INDEX.md`.

## No model training or fine-tuning

This repo only *serves* pre-trained models via vLLM. It does not train,
fine-tune, quantize, or evaluate models. Quantized artifacts come from
upstream accounts (cyankiwi, hesamation, codgician, Intel).
